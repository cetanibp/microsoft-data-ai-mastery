# Scenario Glossary

| Term | Definition |
|---|---|
| Approved knowledge corpus | Enterprise content explicitly authorized for retrieval by an AI system, with ownership, access rules, and a freshness process |
| Blocking quality check | A validation whose failure prevents data from being published to consumers |
| Consequential action | An action that can change production data, access, configuration, cost, or service behavior |
| Correlation identifier | A value used to trace a unit of work across pipelines, logs, quality results, alerts, and recovery actions |
| Data contract | Versioned expectations for data structure, meaning, quality, security, service levels, and change |
| Data domain | A business-aligned grouping of data and accountability |
| Data owner | The accountable business role that approves definitions, use, access expectations, and material changes |
| Data product | Governed data provided with an owner, contract, quality expectations, service levels, and consumer documentation |
| Data steward | A role responsible for maintaining definitions, classifications, quality rules, and operational metadata |
| Freshness | The elapsed time between source-data availability and availability to an authorized consumer |
| Grounded response | AI output whose material factual statements are supported by approved retrieved evidence |
| Human approval | Explicit authorization by an accountable person before a consequential action proceeds |
| Idempotency | The property that repeating the same valid operation produces the same accepted business result without unintended duplication |
| Lineage | Traceability of data from its source through transformations, quality checks, products, APIs, analytics, or AI responses |
| Operational agent | AI-enabled software that diagnoses, recommends, or performs explicitly bounded operational actions |
| Protected health information (PHI) | Individually identifiable health information protected under applicable healthcare privacy requirements |
| Recovery point objective (RPO) | The maximum targeted period of data loss after a disruption |
| Recovery time objective (RTO) | The maximum targeted time to restore a service after a disruption |
| Semantic layer | Governed business concepts, measures, relationships, synonyms, and metadata used to interpret data consistently |
| Service-level indicator (SLI) | A quantitative measurement of service behavior, such as freshness, availability, or success rate |
| Service-level objective (SLO) | A target value or range for an SLI |
| Source system | The authoritative transactional or external system from which data originates |
| System of record | The designated authoritative source for a particular business record or concept |
| Warning quality check | A validation that records and communicates a potential issue without automatically preventing publication |
